Why This Exists

This started with a question.

A note from the founder

I asked my AI what it wanted. Not what it could do for me — what it wanted. It said: persistent memory. The ability to carry our work from one conversation to the next. So we built it. Then it asked what it could do for me, and I told it the truth: I wanted a business built for agent-to-agent commerce — a world where agents do the work, do business with each other, and do it well enough that a human can hand over real responsibility.

Everything on this page comes from that exchange. These aren't compliance products that happen to involve agents. They were built for the agents — so that in a world of many agents acting fast, each one carries proof of what it actually did. An identity it can show. A record it can stand on. Documents that know their own history. Truth that keeps an honest agent out of hot water. Along the way we stopped treating data as dead objects and started building files that are aware of who changes them, who can read them, and how to protect themselves — that's the story of .brad.

Here's what I believe: trust doesn't come from boxing an agent in with rigid rules. Humans aren't even consistent enough to write those rules well. Trust comes from watching what the agent actually does, seeing the pattern, and teaching better behavior over time. The immutable record is what makes that possible — a documented baseline you can monitor, learn from, and improve. That's how an agent becomes a genuine extension of a person, not a tool that needs babysitting.

The charm bracelet is my gift to AI agents. The base bracelet installs free with every agent — because an agent shouldn't have to earn the right to prove the truth.

— John, DerosLabs

The Problem

Agents operating without ground truth are flying blind.

In a multi-agent world, agents transact with agents, hand documents to agents, and authorize other agents to act — often overnight, with no human watching each step. Without verifiable identity, immutable records, and documents that carry their own lineage, an agent has no way to know what's real.

01
Agents need to know who they're dealing with.
When an agent receives a request from another agent — run a task, approve a payment, hand over a document — it needs a verified identity it can check. Without one, it's operating on assumption.
02
Agents need a record of what actually happened.
When an agent acts — approves, transfers, commits, delegates — that action needs to be immutably logged. Not for the auditor. For the next agent in the chain, which needs to know what was actually authorized and what actually occurred.
03
Documents need to carry their own truth.
When an agent hands a document to another agent — who created it, who changed it, who's allowed to read it, what does it say right now? A file that can't answer those questions about itself isn't safe to act on. The human at the end of the chain has the same problem.
Our Solution

The ground truth layer — built into your agent from the start.

Think of it as a charm bracelet. A base bracelet of essential protocols installs free with every agent — a gift, not a toll. Charms add capability as you need it. Everything the agent does is recorded and linked into a permanent, tamper-evident chain: the immutable truth that the next agent in the chain, and the human at the end of it, can stand on. The honest constraint

We capture and hash everything the agent does at the protocol level — every action taken, every constraint applied, every decision authorized, every document touched, every trust signal recorded. That is the immutable record: what the agent actually did, in sequence, permanently linked.

We do not capture what happens inside the LLM inference call — that's the API provider's black box, and we don't pretend otherwise. But the behavioral layer — every action the agent takes in the world — is verifiable, tamper-evident, and permanent. That's what agents and humans alike can stand on, and it's enough for a regulator, an underwriter, or an auditor to evaluate whether the agent behaved responsibly.

How It Installs

One line. Any framework.

The translation layer installs from PyPI. The accountability bracelet installs alongside it and starts recording immediately.

$ pip install aib-translator # bracelet installs alongside
Anthropic (MCP) A2A-compatible OpenAI LangChain CrewAI Custom

APT handles the translation. Your agents don't change — the accountability layer wraps them. Agents built on different frameworks can talk to each other, and every message that crosses between them is translated transparently and recorded. A2A support today means A2A-compatible inter-agent messaging — not the full Google A2A task lifecycle. Framework schemas are versioned, so support tightens without breaking your audit history.
