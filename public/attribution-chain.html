What It Does

Cryptographic chain of custody for every agent spawn event

When one AI agent creates another, something critical must be established before the child agent does anything: who authorized this, what scope was delegated, and which human operator is ultimately responsible. The Attribution Chain Protocol (ACP) makes this record-keeping mandatory at the structural level — not as an optional audit step, but as a pre-execution gate.

Every spawn event produces an Attribution Chain Record (ACR) that captures the parent-child relationship, the delegated task scope, the delegation depth within the hierarchy, and a cryptographic hash linking back to the parent's ACR. That record is anchored to a tamper-evident distributed ledger before the child agent executes its first instruction. If the anchoring fails, the spawn is blocked.

The result is a complete, independently verifiable chain of custody from the top of any AI agent hierarchy down to the deepest sub-agent — with every node in the chain cryptographically bound to the one above it, and every node's authority traceable back to a human operator.

How It Works

Pre-execution blocking enforces the chain

1
Spawn request initiated
A parent agent requests to spawn a child agent with a defined task scope. The spawn request is intercepted by the ACP Middleware Layer before any execution occurs.
2
ACR constructed
An Attribution Chain Record is generated containing: spawning and spawned agent IDs, human operator ID, task scope hash, delegation depth, parent ACR hash, spawn timestamp, and spawning agent signature.
3
Ledger anchoring (blocking gate)
The ACR is submitted to the tamper-evident distributed ledger. This step blocks child agent execution until the anchor is confirmed. The anchor ID is embedded in the ACR, making it verifiable by any third party.
4
Child agent authorized
Only after the ACR is anchored and confirmed does the child agent receive authorization to execute. The chain is now immutable: the spawn event, its scope, and its human-operator attribution are locked in the ledger.
5
Chain verifiable
Any party can traverse the attribution chain from any agent upward to the human operator — verifying each cryptographic link independently. Completeness proofs confirm no gaps exist in the chain.
Why It Matters

Attribution before action, not after

In multi-agent AI systems, tracing which human operator authorized a specific action by a deeply nested sub-agent is currently impossible or reconstructed after the fact — if at all. The ACP solves this by making the attribution record a pre-condition of execution, not a post-hoc audit artifact.

When something goes wrong — or when compliance requires proof of authorization — the attribution chain is already there, immutable, anchored, and independently verifiable. Every agent in any hierarchy built on ACP carries a complete traceable lineage back to a human.
